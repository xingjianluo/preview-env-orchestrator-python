# 预览环境编排器（本地可运行）

用本地内存状态模拟环境资源与配额的预览环境编排服务，保证并发申请、失败重试
与超时回收下状态一致且可解释。完整设计见 [`docs/design.md`](docs/design.md)。

## 快速开始

```bash
uv sync
uv run pytest                       # 60 个单测（存储/生命周期/配额/并发/标识轮换接管/HTTP）
uv run uvicorn main:app --port 8000 # 启动服务
```

## 核心能力

- **按项目+分支申请独立环境**：`request_key` 为幂等键，重复提交复用已有环境，
  不重复创建、不重复计数；配额耗尽（429）、标识冲突（409）、参数非法（400）
  分别返回可区分的错误码。
- **同分支标识轮换自动接管（单活）**：同一 `project+branch` 任意时刻最多一份
  存活环境。CI 重跑带来新 `request_key` 时默认**接管**同一份环境（复用 env_id
  与资源、不新增配额），租约从接管时刻重新起算；老标识此后在查询/续期/回收/
  重试/再申请上都得到确定一致的 `IDENTIFIER_SUPERSEDED`（409），不会出现两个
  标识同时指向一份环境。已过期环境先即时回收、只能新建，不会被接管“救活”。
- **到期实时生效**：过期无需手动触发清理，任意一次查询/续期/接管/申请/配额
  快照进入时都会先惰性回收已到期环境，立即返回 410 并释放资源与容量。
- **完整生命周期**：`provisioning → ready / failed → reclaimed`；
  创建失败可重试且无重复资源；TTL 到期或显式回收释放资源；重复回收安全；
  已回收环境不可访问（410）。
- **并发一致性**：单锁 + 同键创建串行化 + 分支单活索引 + 配额槽位原子占用，
  绝不超发、无资源/槽位空洞；接管与续期、显式回收、超时回收、并发申请竞争时
  结论确定可复现（含 32 路并发换标识、provisioning 途中接管等测试）。
- **可解释日志**：每个请求打印请求键、状态流转、接管动作与拒绝依据。

## 主要接口

`POST /environments`、`GET /environments/{key}`、
`POST /environments/{key}/renew`、`POST /environments/{key}/retry`、
`DELETE /environments/{key}`、`POST /reap`、`GET /quota`。
